# Madzera — Feature 042: Readable Case and Customer References

**Date:** 20 October 2026
**Status:** Implemented and regression-tested locally; hosted deployment pending
**Migration:** `database/migrations/042_case_queue_readable_references.sql`
**Regression test:** `database/tests/027_case_queue_readable_references.sql`

## 1. Purpose

Display human-readable case and customer references in employee workflows
while retaining UUIDs as internal database identifiers.

Examples:

- Case: `CAS2026000001`
- Customer: `CUS000001`

References are generated by Migration 040. Migration 042 exposes existing
references through the case queue; it does not allocate new references.

## 2. Database Changes

Migration 042 replaces `public.get_case_queue()` with an extended
return signature.

The original 12 result columns are retained in their existing order.
Three columns are appended:

| Column | Type | Purpose |
|---|---|---|
| `case_reference` | TEXT | Readable case identifier |
| `customer_reference` | TEXT | Readable customer identifier, nullable |
| `customer_name` | TEXT | Customer display name, nullable |

The queue continues to filter cases by the current employee's organisation.

Customer information is joined using both customer ID and organisation ID.

Existing active-lock visibility is retained.

## 3. Frontend Integration

Updated components:

- `web/src/app/cases/CasesWorkspace.tsx`
- `web/src/app/cases/[caseId]/CaseWorkspace.tsx`

The case queue displays readable case references and customer information.

Queue search supports both readable case references and UUIDs.

The case-creation success display looks up the newly created readable
reference through the queue RPC.

The case detail heading displays the readable case reference after the
exclusive case session is acquired.

The customer-reference detail field displays the readable customer
reference where one is linked, or `No customer linked` otherwise.

The customer-reference lookup associates results with the case UUID
and customer UUID to avoid displaying a result for the wrong case.

## 4. Compatibility and Scope

UUIDs remain the database primary keys and internal navigation identifiers.

Migration 042 does not modify:

- Reference generation or protection triggers
- Case creation RPCs
- Case-lock acquisition, renewal or release functions
- Case audit events
- Existing case/customer associations

The queue RPC return signature changes, so frontend and database versions
must be coordinated during deployment.
